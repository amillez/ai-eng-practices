# Steal from pstack

What we adopt from poteto's pstack vs what we only link. pstack skills are plain `SKILL.md` files, so the ideas port to Claude Code / Codex without the Cursor plugin. Do **not** wholesale-install pstack on `agent-m1`. poteto-mode itself is the `amillez-mode` skill (below).

## Adopted

- **poteto-mode → `amillez-mode`.** Lives in `amillez/akit` as [`skills/amillez-mode`](https://github.com/amillez/akit/tree/main/skills/amillez-mode), pinned to pstack 0.15.28 (`d457567`). It carries the 24 principles, technical-writing, tdd, and the ported playbooks, remapped to our lanes, Argent and `verify-*` proof, and never-merge. Required for every coding agent (single or Orca worker) per [agent use policy](../policies/agent-use-policy.md#1-coding-host-routing). Grok Bots attach it on dispatch; they do not load it themselves. The worker brief template and retry by failure mode from pstack `orchestrate.md` live in `orchestrate-agents`. Per-file verdicts: [`UPSTREAM.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/UPSTREAM.md). Pointer: [amillez-mode](amillez-mode.md).
- **Babysit until merged.** In [agent-dispatch-lifecycle.md](agent-dispatch-lifecycle.md#babysit-until-merged), aligned with pstack's babysit playbook: drive the PR through conflicts, review, and CI; do not drop it when the agent goes idle. The bot owns the workstream until `merged` | `discarded`, arms a finite session-settle watch, and babysits the open PR with PR-scoped GitHub event listeners. The coding agent's side of a babysit is amillez-mode `playbooks/babysit.md`.
- **Prove it works** — maps to [agent-proof-feedback-loop.md](agent-proof-feedback-loop.md). Real artifact evidence (sims, screens, logs), not "it compiles." Launch, Doctor, Drive, and Evidence on the real surface; the agent inspects the proof against the success criteria; media on the `media` branch.
- **Blast radius.** The separate core skill [`blast-radius`](https://github.com/amillez/akit/blob/main/skills/blast-radius/SKILL.md), run only by an explicit `/blast-radius` and named by amillez-mode's trigger for a diff you don't trust. For a small diff you do not fully trust, find the *one fact* the change is safe because of and prove it by running real code, not a convincing writeup. amillez-mode's PR-body Blast Radius section and review triage link it.
- **Show me your work.** The separate core skill [`show-me-your-work`](https://github.com/amillez/akit/blob/main/skills/show-me-your-work/SKILL.md), run by an explicit `/show-me-your-work` and named by amillez-mode's trigger for long, autonomous, or later-reviewed work. It keeps a decision trail as one TSV log with one row per decision. It ships with its TSV template in `references/decision-log-template.tsv` and its logging helper `scripts/log.sh`. The log stays local by default and gets committed when a reviewer needs an auditable record. amillez-mode's Hillclimb, Autonomous run, Pause safely, and Session pickup playbooks and the `figure-it-out` skill link it.
- **Figure it out.** The separate core skill [`figure-it-out`](https://github.com/amillez/akit/blob/main/skills/figure-it-out/SKILL.md), run by an explicit `/figure-it-out` and named by amillez-mode's size-gate rule and by `orchestrate-agents`. It is the single-agent path for long, cross-cutting, or later-reviewed work. The one-line rule is in the [size gate](../policies/agent-use-policy.md#1-coding-host-routing). Needs parallel workers → Orca. One agent owns the whole loop → `figure-it-out`.
- **Recall.** Part of amillez-mode [`playbooks/session-pickup.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/session-pickup.md) as a shared-record sweep (git history, reverts, `gh` issues and PRs, connected trackers, committed decision trails). No separate skill.
- **TypeScript best practices.** The separate core skill [`typescript-best-practices`](https://github.com/amillez/akit/blob/main/skills/typescript-best-practices/SKILL.md), on the [skills allowlist](agent-proof-feedback-loop.md#skills-allowlist). Grounds amillez-mode's type-system and boundary principles in TypeScript. Defers React Native library usage to `react-native-best-practices`.
- **Correct.** The separate core skill [`correct`](https://github.com/amillez/akit/blob/main/skills/correct/SKILL.md), run only by an explicit `/correct` and named by amillez-mode's trigger for a mistake Agustín corrects a second time. It finds the mistake classes agents keep repeating in a repo and makes each one impossible at the highest level that works: architecture, then types, then a lint or CI check whose error names the fix, then behavior tests, and agent rules last. It applies [Hard constraints](hard-constraints.md) to one repo at a time, proves each new check fails on a real past mistake, and keeps a rule table in the project's agent instruction file.
- **Reflect.** The separate core skill [`reflect`](https://github.com/amillez/akit/blob/main/skills/reflect/SKILL.md), run only by an explicit `/reflect` and named by amillez-mode's trigger when Agustín asks to reflect on a session. It is the one pstack fan-out skill we adopted. Three reviewers on different lanes read a finished Claude Code or Codex session log, a synthesizer on Opus 5.5 xHigh filters the learnings, and the result is one small PR for review (never merged) or a hand-off to the weekly garden. It never edits installed skills in place.
- **Code-review brief.** amillez-mode [`references/code-review.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/references/code-review.md) carries the reviewer prompt, rubric, severity scale, approval bar, and lead-judgment filters from pstack `interrogate`. One reviewer runs it, per the [Review row](../policies/agent-use-policy.md#1-coding-host-routing). Its definition of a blocking finding is what [fleet norms rule 9](../policies/fleet-norms.md) means by "no blocking findings".
- **Unslop.** The separate core skill [`unslop`](https://github.com/amillez/akit/blob/main/skills/unslop/SKILL.md), verbatim from pstack, run by an explicit `/unslop` and named by amillez-mode's trigger for any prose surface, including agent replies. amillez-mode's technical-writing reference, its Investigation and Opening a PR playbooks, and the `show-me-your-work` and `blast-radius` skills link it.
- **Sharpen.** The separate core skill [`sharpen`](https://github.com/amillez/akit/blob/main/skills/sharpen/SKILL.md), verbatim from pstack and run only by an explicit `/sharpen`. Before starting a task, it checks how a top expert would approach it, what the user is really after, and whether the task is over- or underspecified, then folds in only what makes the work better and always keeps one outside check that the result is right.
- **Project verification skill pattern.** `create-verification-skill` + `maintain-verification-skill` in `amillez/akit` `skills/`, with an **amillez-mode overlay** (not a wholesale pstack install):
  - Keep: interview repo → generate `verify-<app>` → feature map shape → prove before handoff → maintain-loop rigor. Evidence dry-run nuance: some dry-runs still touch network/browser — observe what they skip, do not trust the name.
  - Overlay: default output under project-local `.claude/skills/verify-<app>/` and/or `.agents/skills/verify-<app>/` (never `.cursor/skills/`); generate/prove on an [Orca host](../policies/agent-use-policy.md#12-orca-hosts-and-resource-limits); Argent for Expo/RN; screenshots/videos → `media` branch, inspected against the success criteria ([agent-proof-feedback-loop](agent-proof-feedback-loop.md), [agent-use-policy](../policies/agent-use-policy.md), [amillez-mode](amillez-mode.md)).
  - **Bot designer (Stella):** day-one wiring for coding bots on driveable apps — point at create + maintain; skip for pure library/docs/non-coding bots. Host stays agent-m1-first in the bot brief.
  - Next use: generate for Expo/RN apps (Favvy, asnt) via Argent Drive/Evidence.
- **Formal verification pair.** The separate core skills [`create-formal-verification-skill`](https://github.com/amillez/akit/blob/main/skills/create-formal-verification-skill/SKILL.md) and [`maintain-formal-verification-skill`](https://github.com/amillez/akit/blob/main/skills/maintain-formal-verification-skill/SKILL.md), each run only by its explicit slash command. The create skill finds the code where a bug costs most and tests reach least, verifies one property with the tool that fits (TLA+ by default for event-order questions), and leaves a project-local skill that rechecks it. The maintain skill brings that check back in line after the code changes and says whether a failure is drift or a bug. Our overlay puts the project skill under `.claude/skills/` and `.agents/skills/`. A verifier that becomes a project dependency follows the [dependency age rule](../policies/agent-use-policy.md#11-dependency-versions).
- **`setup-pstack` → thin `setup-amillez-models`.** A policy pointer only (`skills/setup-amillez-models`). Points at the [agent-use-policy](../policies/agent-use-policy.md) chooser (Claude Haiku 5.5 Max / Opus 5.5 High / Grok 4.7 xHigh fallback over 70% Claude Code usage / Fable 5.1 / GPT 6.1 Sol for review). Does **not** write `~/.cursor/rules/pstack-models.mdc` or copy pstack role maps; our lanes come from the policy, not pstack defaults. Optional offer to run `/create-verification-skill`. Stella: day-one wiring for coding bots.
- **Worktree cleanup.** Required in dispatch teardown (plus sim/Metro teardown), and amillez-mode `playbooks/worktree-cleanup.md` with a read-only `scripts/worktree-audit.sh`.
- **Explain the Number.** amillez-mode [`principles/explain-the-number.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/principles/explain-the-number.md). Before you trust, report, or act on a measured number, name what limits it and rule out that it measured something else. Perf issue and Hillclimb vet their numbers against it.
- **Hard constraints** — reinforced by poteto's GrokBot workshop: enforce footguns in lint/CI so the proof loop fails closed. See [hard-constraints.md](hard-constraints.md).

## Steal selectively later

- **Autopilot verification rounds.** From pstack autopilot: verification *rounds* that re-run when the code-ready head changes, and a small `children.tsv` (or equivalent) so the owner tracks subagents and only posts status when a tracked item changed. Port the idea into eng-bot babysit notes, not pstack's autopilot scripts.
- **Shipping.** Not part of amillez-mode. Coding agents never merge. Bots merge per [fleet norms rules 8 and 9](../policies/fleet-norms.md). The idea worth keeping is independent verification (a different agent verifies than the one that wrote).
- **Fan-out skills (`how`, `why`, `architect`, `arena`, `swarm`, `interrogate`).** Not part of amillez-mode. `reflect` is the one ported, above. From `interrogate` we adopted only the reviewer brief (Code-review brief, above). `interrogate`'s multi-model fan-out is still deferred. Use read-only recon and a plan ([agent use policy §5](../policies/agent-use-policy.md#5-plan-before-build-non-trivial-work)). Settle an empirical open question (behavior, timing, layout, perf, whether an approach works) with amillez-mode's [Prototype](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/prototype.md) playbook first. Keep `grill-me` for contested product or preference calls a prototype can't settle. Don't run an adversarial review over an abstract plan. For a one-way-door decision, a second opinion is the same prompt on a different lane. Structured multi-agent fan-out is an **Orca** Run with an Opus 5.5 xHigh coordinator ([big-work-orchestration.md](big-work-orchestration.md)). Revisit only if those fall short.
- **Benchmark checklist.** pstack's `benchmark-checklist` skill vets a perf number with seven questions (limiter, tuning, limits, errors, repeat runs, end-to-end relevance, whether the work happened). It is a separate port that pairs with amillez-mode Perf issue and Hillclimb.
- **Auto-reproduce user reports (later).** A scheduled Grok Bot routine watches a feedback channel and tries to reproduce each report with the project's `verify-<app>` skill, then reports back with evidence (poteto guide Pt. 1). Reproduce and report only, no auto-fix. Worth doing once the verify skills and their app CLIs are solid.
- **Post-merge rollout watch (idea only).** Cursor's Rollouts bot (Sep 2026) watches PR → deploy against a monitoring plan and telemetry. If we want the pattern, sketch a Grok Bot routine with a PagerDuty or Sentry listener after merge.

## Link only / skip for now

- Upstream `/poteto-mode` as a Cursor sticky mode. We run `amillez-mode` in Claude Code and Codex instead.
- `/poteto-help`, a Cursor plugin help command.
- Comment Sicko / no-comments culture — optional taste, not policy.
- Benny Slack automations pack — out of scope.
- Wholesale `npx` / plugin install of every pstack skill onto `agent-m1`. That includes upstream's Claude Code plugin (`/plugin install pstack@cursor-plugins`, pstack 0.15.26 and later), whose adapter maps Cursor names and roles to pstack defaults, while amillez-mode and our ported skills already run in Claude Code and Codex on our lanes.
- Transcript / routine healthcheck *skill recipes* — we use Grok Bot routines, not poteto skill bodies.
- Slash skill `ketchup` (catch-up summaries). It relies on Cursor chat, `/bro`, and `/visualize`.
- Slash skill `in-your-own-words` (goal restatement). amillez-mode already restates the goal first in Bug fix and Investigation and in dispatch launches.
