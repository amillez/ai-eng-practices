# Steal from pstack

What we adopt from poteto's pstack vs what we only link. pstack skills are plain `SKILL.md` files, so the ideas port to Claude Code / Codex without the Cursor plugin. Do **not** wholesale-install pstack on `agent-m1`. poteto-mode itself is the `amillez-mode` skill (below).

## Adopted

- **poteto-mode → `amillez-mode`.** Lives in `amillez/akit` as [`skills/amillez-mode`](https://github.com/amillez/akit/tree/main/skills/amillez-mode), pinned to pstack 0.15.5 (`ecc249f`). It carries the 23 principles, unslop, technical-writing, tdd, and the ported playbooks, remapped to our lanes, Argent and `verify-*` proof, and never-merge. Required for every coding agent (single or Orca worker) per [agent use policy](../policies/agent-use-policy.md#1-coding-host-routing). Grok Bots attach it on dispatch; they do not load it themselves. The worker brief template and retry by failure mode from pstack `orchestrate.md` live in `orchestrate-agents`. Per-file verdicts: [`UPSTREAM.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/UPSTREAM.md). Pointer: [amillez-mode](amillez-mode.md).
- **Babysit until merged.** In [agent-dispatch-lifecycle.md](agent-dispatch-lifecycle.md#babysit-until-merged), aligned with pstack's babysit playbook: drive the PR through conflicts, review, and CI; do not drop it when the agent goes idle. The bot owns the workstream until `merged` | `discarded`, arms a finite session-settle watch, and babysits the open PR with PR-scoped GitHub event listeners. The coding agent's side of a babysit is amillez-mode `playbooks/babysit.md`.
- **Prove it works** — maps to [agent-proof-feedback-loop.md](agent-proof-feedback-loop.md). Real artifact evidence (sims, screens, logs), not "it compiles." Launch, Doctor, Drive, and Evidence on the real surface; the agent inspects the proof against the success criteria; media on the `media` branch.
- **Blast radius.** amillez-mode [`playbooks/blast-radius.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/blast-radius.md). For a small diff you do not fully trust, find the *one fact* the change is safe because of and prove it by running real code, not a convincing writeup. It has its own router entry and is linked from the PR body's Blast Radius section and from review triage.
- **Show me your work.** amillez-mode [`references/show-me-your-work.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/references/show-me-your-work.md), with its TSV template and `scripts/decision-log.sh`. Hillclimb and Autonomous run point at this reference, and a trigger in amillez-mode's Non-negotiables requires a decision trail for long, autonomous, or later-reviewed work.
- **Figure it out.** amillez-mode [`playbooks/figure-it-out.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/figure-it-out.md). The single-agent path for long, cross-cutting, or later-reviewed work. The one-line rule is in the [size gate](../policies/agent-use-policy.md#1-coding-host-routing). Needs parallel workers → Orca. One agent owns the whole loop → Figure it out.
- **Recall.** Part of amillez-mode [`playbooks/session-pickup.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/session-pickup.md) as a shared-record sweep (git history, reverts, `gh` issues and PRs, connected trackers, committed decision trails). No separate skill.
- **TypeScript best practices.** The separate core skill [`typescript-best-practices`](https://github.com/amillez/akit/blob/main/skills/typescript-best-practices/SKILL.md), on the [skills allowlist](agent-proof-feedback-loop.md#skills-allowlist). Grounds amillez-mode's type-system and boundary principles in TypeScript. Defers React Native library usage to `react-native-best-practices`.
- **Reflect.** amillez-mode [`playbooks/reflect.md`](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/reflect.md), the one fan-out skill ported. Explicit invoke only. Three reviewers on different lanes read a finished Claude Code or Codex session log, a synthesizer on Opus 5.5 xHigh filters the learnings, and the result is one small PR for review (never merged) or a hand-off to the weekly garden. Installed skills are never edited in place.
- **Project verification skill pattern.** `create-verification-skill` + `maintain-verification-skill` in `amillez/akit` `skills/`, with an **amillez-mode overlay** (not a wholesale pstack install):
  - Keep: interview repo → generate `verify-<app>` → feature map shape → prove before handoff → maintain-loop rigor. Evidence dry-run nuance: some dry-runs still touch network/browser — observe what they skip, do not trust the name.
  - Overlay: default output under project-local `.claude/skills/verify-<app>/` and/or `.codex/skills/verify-<app>/` on agent-m1 only (never `.cursor/skills/`); generate/prove on agent-m1; Argent for Expo/RN; screenshots/videos → `media` branch, inspected against the success criteria ([agent-proof-feedback-loop](agent-proof-feedback-loop.md), [agent-use-policy](../policies/agent-use-policy.md), [amillez-mode](amillez-mode.md)).
  - **Bot designer (Stella):** day-one wiring for coding bots on driveable apps — point at create + maintain; skip for pure library/docs/non-coding bots. Host stays agent-m1-first in the bot brief.
  - Next use: generate for Expo/RN apps (Favvy, asnt) via Argent Drive/Evidence.
- **`setup-pstack` → thin `setup-amillez-models`.** A policy pointer only (`skills/setup-amillez-models`). Points at the [agent-use-policy](../policies/agent-use-policy.md) chooser (GPT 6 Luna Max / Opus 5.5 High / GPT 6.1 Sol fallback over 70% Claude Code usage / Fable 5.1). Does **not** write `~/.cursor/rules/pstack-models.mdc` or copy pstack role maps; our lanes come from the policy, not pstack defaults. Optional offer to run `/create-verification-skill`. Stella: day-one wiring for coding bots.
- **Worktree cleanup.** Required in dispatch teardown (plus sim/Metro teardown), and amillez-mode `playbooks/worktree-cleanup.md` with a read-only `scripts/worktree-audit.sh`.
- **Hard constraints** — reinforced by poteto's GrokBot workshop: enforce footguns in lint/CI so the proof loop fails closed. See [hard-constraints.md](hard-constraints.md).

## Steal selectively later

- **Autopilot verification rounds.** From pstack autopilot: verification *rounds* that re-run when the code-ready head changes, and a small `children.tsv` (or equivalent) so the owner tracks subagents and only posts status when a tracked item changed. Port the idea into eng-bot babysit notes, not pstack's autopilot scripts.
- **Shipping.** Not part of amillez-mode. Agents never merge; only Agustín's say-so merges. The idea worth keeping is independent verification (a different agent verifies than the one that wrote).
- **Fan-out skills (`how`, `why`, `architect`, `arena`, `swarm`, `interrogate`).** Not part of amillez-mode. `reflect` is the one ported, above. Use read-only recon and a plan ([agent use policy §5](../policies/agent-use-policy.md#5-plan-before-build-non-trivial-work)). Settle an empirical open question (behavior, timing, layout, perf, whether an approach works) with amillez-mode's [Prototype](https://github.com/amillez/akit/blob/main/skills/amillez-mode/playbooks/prototype.md) playbook first. Keep `grill-me` for contested product or preference calls a prototype can't settle. Don't run an adversarial review over an abstract plan. For a one-way-door decision, a second opinion is the same prompt on a different lane. Structured multi-agent fan-out is **Orca** on `agent-m1` with an Opus 5.5 xHigh coordinator ([big-work-orchestration.md](big-work-orchestration.md)). Revisit only if those fall short.
- **Auto-reproduce user reports (later).** A scheduled Grok Bot routine watches a feedback channel and tries to reproduce each report with the project's `verify-<app>` skill, then reports back with evidence (poteto guide Pt. 1). Reproduce and report only, no auto-fix. Worth doing once the verify skills and their app CLIs are solid.
- **Post-merge rollout watch (idea only).** Cursor's Rollouts bot (Sep 2026) watches PR → deploy against a monitoring plan and telemetry. If we want the pattern, sketch a Grok Bot routine with a PagerDuty or Sentry listener after merge.
